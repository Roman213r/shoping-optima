# Ручний QA — Optima Smart

Автотести лежать **у коді репозиторію**, а GitHub їх лише запускає:

- `npm test` — швидкі unit-тести (Vitest), без браузера
- `npm run test:e2e` — сценарії в Chromium (Playwright); один раз: `npx playwright install chromium`
- на GitHub: `.github/workflows/tests.yml` (після push/PR у **Actions**)

Ручний чеклист нижче — для того, що автотест не замінює (вигляд, мобільна верстка, крайові кейси).

Нижче — що перевіряти руками (те, що автотест не покриває або покриває частково).

## Каталог

- [ ] На головній видно картки з фото, ціною і кнопкою «Купити».
- [ ] Сторінка 2 відкривається і товари інші, ніж на сторінці 1.
- [ ] Фільтр «Живлення» не ховає весь каталог; є посилання «Відкрити всі сторінки каталогу».
- [ ] Пошук «люстра» / «пилосос» / «хаб» знаходить відповідні товари.
- [ ] Пошук нісенітниці показує «Нічого не знайдено».
- [ ] Відкриття картки веде на `/product/...` з описом і ціною.

## Кошик

- [ ] «Купити» збільшує лічильник у шапці.
- [ ] У кошику можна змінити кількість +/- і рядок зникає при 0.
- [ ] Без логіну кнопка веде на «Увійдіть, щоб оформити».
- [ ] Після оновлення сторінки товари в кошику лишаються (localStorage).

## Акаунт

- [ ] Реєстрація з унікальним email заходить і показує ім’я в шапці.
- [ ] Повторна реєстрація того ж email — помилка.
- [ ] Вхід з неправильним паролем — помилка.
- [ ] «Вийти» прибирає сесію; кошик при цьому не обов’язково чиститься.

## Контент і футер

- [ ] Новини → стаття відкривається.
- [ ] Акції, Доставка, Гарантія, Контакти, Про нас, Повернення відкриваються з шапки/футера.
- [ ] На вузькому екрані (~375px) шапка, пошук і сітка карток читабельні.

## Регресія після змін

- [ ] `npm run dev` з папки `shoping-optima`.
- [ ] Картинки товарів тематичні; якщо фото не вантажиться — є запасна іконка, сторінка не падає.
